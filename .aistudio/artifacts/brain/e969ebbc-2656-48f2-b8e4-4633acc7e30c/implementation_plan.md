# AI Studio Code Assistant GitHub ZIP Sync & Diff Workbench

Comprehensive engineering architecture and implementation plan to introduce a high-performance **ZIP Sync & Tree Alignment Workbench** into the Git Manager application. This feature allows developers working with Google AI Studio, local code exports, or zip bundles to effortlessly synchronize, inspect diffs, re-align nested root folder discrepancies, and commit multi-file changes to GitHub repositories either via direct atomic commits or pull requests.

## 1. Objective & Core Concept

### Purpose
To close the gap between editing code in AI Studio (or offline tools) and syncing it back to a GitHub repository by providing an AI Studio-style ZIP Sync tool that understands folder tree misalignments, previews current vs incoming repository trees, presents clear diffs, and commits cleanly.

### Success & Acceptance Criteria
1. **Reference Repository Tree**: Before or during upload, user can view and search the existing repository tree structure so they know what file hierarchy is expected.
2. **ZIP Ingestion & Analysis**: User can drag-and-drop or upload any `.zip` file.
3. **Automatic Alignment Engine**: Detects if all files in the ZIP share a common root directory prefix (e.g., `git-manager-main/src/...` vs `src/...`) and automatically suggests or aligns the root. Allows manual base path adjustment if needed.
4. **Interactive Checklist**: Grouped by **Added** (green), **Modified** (blue), **Removed** (red), and **Unchanged** (gray). Users can select all or toggle individual files.
5. **Syntax-Highlighted Diff Viewer**: Side-by-side or unified diff viewing with line changes for any modified file before committing.
6. **Commit & PR Dispatcher**:
   - Single atomic commit via GitHub Git Trees API for all selected files.
   - Option to commit directly to current branch or create a new branch and open a Pull Request.
   - Support for offline/demo mode storing changes in local storage.

## 4. Technical Implementation & Data Strategy

### GitHub Git Data API Strategy (Atomic Commit)
Instead of sequentially pushing files via the high-level contents API (which would create dozens of individual commits and trigger rate limits), we implement the Git Data Trees API:
1. `GET /repos/{owner}/{repo}/git/ref/heads/{branch}` -> Retrieve latest commit SHA.
2. `GET /repos/{owner}/{repo}/git/commits/{commit_sha}` -> Retrieve base tree SHA.
3. For added and modified files:
   - Convert content to UTF-8/Base64.
   - Call `POST /repos/{owner}/{repo}/git/blobs` -> returns blob SHA.
4. Call `POST /repos/{owner}/{repo}/git/trees`:
   - `base_tree`: base tree SHA.
   - `tree`: array of `{ path, mode: '100644', type: 'blob', sha: blobSha }` for additions/modifications, and `{ path, mode: '100644', type: 'blob', sha: null }` for removed files.
5. Call `POST /repos/{owner}/{repo}/git/commits`:
   - `parents`: `[commit_sha]`
   - `tree`: new tree SHA
   - `message`: user commit message
6. Apply ref:
   - Direct: `PATCH /repos/{owner}/{repo}/git/refs/heads/{branch}` with new commit SHA.
   - Branch + PR: `POST /repos/{owner}/{repo}/git/refs` (`refs/heads/{newBranch}`) then `POST /repos/{owner}/{repo}/pulls`.

### Offline & Demo Fallback Strategy
If unauthenticated or running in demo mode:
- Modifies `localStorage` files for `local_file_${repoName}_${filePath}`.
- Updates `activeFiles` and creates a local commit entry.
- Alerts user with a success confirmation toast.
